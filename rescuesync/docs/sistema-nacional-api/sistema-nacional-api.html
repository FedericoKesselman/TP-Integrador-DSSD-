Sistema Nacional de Gestión de Recursos y Riesgos (0.1.0)

Download OpenAPI specification:

License: Uso académico — TP integrador DSSD 2026

API REST del Sistema Nacional (SN) de RescueSync. Gestiona ONGs y su stock de recursos, valida ofertas por niveles de competencia y compromete/libera recursos con locking en PostgreSQL.

Autenticación: POST /auth/login devuelve un JWT (HS256, 1 h). El resto de los endpoints, salvo /health y /docs, exige Authorization: Bearer <token>. Usá el botón Authorize con el token.

Errores: siempre { "message": "..." } con el código HTTP correcto (400, 401, 403, 404, 409).

Contrato completo: docs/api-contracts-sistema-nacional.md.

Validación y compromiso

Validación por niveles de competencia y compromiso transaccional con locking.

Evalúa ofertas por niveles de competencia

Rol: integracion. Lee el stock de las ONGs de las ofertas con SELECT ... FOR UPDATE (ordenado por id) dentro de una transacción; no reserva. Si hay una reserva o un cierre en curso sobre ese stock, espera a que termine y lee el valor ya actualizado. Nunca rechaza en forma binaria: toda oferta recibe un perfil.

Cómo se calcula el perfil de cada oferta

  • Por ítem: cantidadHabilitada = min(cantidadOfrecida, disponible sumado de las ONGs de la oferta). Disponible = total − comprometido, solo de ONGs habilitadas.
  • Cobertura de la oferta = promedio de la cobertura de cada ítem (habilitado / ofrecido).
  • nivelHabilitacion: PLENO (100 %), PARCIAL (≥ 50 %), APOYO (> 0 %) o SIN_CAPACIDAD (0 %). rolSugerido es principal para PLENO y PARCIAL, y apoyo para el resto.
  • nivelRiesgoPermitido: el menor entre el nivel operativo de las ONGs de la oferta (1 = baja, 2 = media, 3 = alta, 4 = critica) y un tope por cobertura (PLENO → critica, PARCIAL → alta, APOYO → media, SIN_CAPACIDAD → baja).
  • Una ONG inexistente o no habilitada no cuenta y se avisa en observaciones; no rechaza el pedido.
  • resumen.cobertura[].cubierta suma lo habilitado de todas las ofertas para ese lote, con tope en solicitada. Sin ofertas, resultados es [] y todosLosLotesCubiertos es false.

La validación no reserva: dos ofertas de la misma ONG ven el mismo stock. Lo controla POST /compromisos, que responde 409 si falta.

Responde 400 con detalle por campo si el body no respeta el formato (ej. ofertas[0].items[0].loteId).

Reserva transaccional de las ofertas adjudicadas

Rol: integracion. Reserva el stock de las ofertas adjudicadas dentro de una transacción, bloqueando cada fila de stock con SELECT ... FOR UPDATE.

  • Reparte entre las ONGs de la oferta: principal primero, cada una hasta su disponible. reparto trae una fila por ONG y recurso.
  • El stock se comparte entre las ofertas del pedido: cada oferta ve lo que dejó la anterior.
  • Todo o nada: si algún recurso no alcanza responde 409 y no reserva nada (tampoco las ofertas anteriores del pedido). detalle trae ofertaId, recursoCodigo, solicitado, disponible, faltante y ongs ([{ ongRef, disponible }], lo que tenía cada ONG de la oferta).
  • Idempotente por (emergenciaId, ofertaId), también ante reintentos en paralelo: si la oferta ya estaba comprometida no reserva de nuevo y la devuelve con yaExistia: true, su reparto original y su estado (liberado si el proyecto ya se cerró). El cuerpo del reintento no se compara: manda el compromiso original.
  • Orden de locks: primero compromisos, después ong_recursos por id.
  • Responde 400 con detalle por campo si el body no respeta el formato (ej. ofertas[0].items[0].cantidad).
